# المعمارية — Endless World

## المبدأ الأساسي

كل شيء في العالم يُحسب **على الطلب** (on-demand) وبشكل **حتمي** (deterministic) من البذرة.
لا يوجد عالم مخزّن بالكامل؛ التوليد الحتمي يسمح بإعادة بناء أي جزء في أي وقت.

## الطبقات والمسؤوليات

| الملف | المسؤولية |
|---|---|
| `seed.ts` | هوية العالم (توليد، حفظ، تحميل) |
| `random.ts` | أدوات حتمية (hash) — الأساس لأي توليد إجرائي مستقبلي |
| `terrainGenerator.ts` | ارتفاع السطح السلس لأي `x` من البذرة (value noise) |
| `blockTypes.ts` | تعريفات الكتل الثابتة (id, color, solid) |
| `chunk.ts` | رياضيات الكتل/الوحدات (أفقي + رأسي `chunkY` + نطاقات 2D) + حاوية `Chunk` (مخزن البيانات + علم `modified`) |
| `chunkGenerator.ts` | يملأ بيانات الوحدة حتماً من (بذرة، index، chunkY) — Air/سطح/Stone |
| `world.ts` | مالك العالم: ذاكرة وحدات ثنائية الأبعاد + hot-cache + تتبع التعديلات + حساب/تطبيق فروق الحفظ |
| `saveSystem.ts` | تنسيق الحفظ (seed + موضع اللاعب + الفروق) والتسلسل والتحقق من الإصدار |
| `player.ts` | فيزياء اللاعب — تصادم AABB ضد شبكة الكتل (محاور منفصلة + خطوات فرعية) |
| `camera.ts` | يتبع اللاعب بنعومة؛ يحدد النطاق المرئي |
| `pointer.ts` | حالة الفأرة الخام (موضع + أزرار) |
| `blockInteraction.ts` | التفاعل: استهداف + هدم/وضع (السياسة) |
| `blockRenderer.ts` | يرسم الكتل المرئية فقط، وحدةً وحدة |
| `render.ts` / `main.ts` | تركيب المشهد وحلقة اللعبة |

## تدفق البيانات في كل إطار

```
input → player.update → position
camera.follow(player) → نطاق مرئي
pointer + camera → blockInteraction.update → setBlockAt (إن وُجد إجراء)
blockRenderer.render(camera, world) → getChunksInRange → getBlockAt → رسم
```

## كيف يتوسع العالم

- **0.2 / 0.3:** العالم دالة سلسة (height-map) تُرسم بلا حدود.
- **0.4:** تحوّل إلى شبكة كتل مخزّنة في وحدات؛ الأساس لكل تفاعل (بناء/هدم/حفظ).
- **0.5:** أول نظام تفاعل — هدم ووضع بالماوس (يرى اللاعب النتيجة فوراً).
- **0.5.1:** وحدات ثنائية الأبعاد `chunkY` — رفع القيد الرأسي؛ البناء يرتفع بلا سقف
  (كان محصوراً بعمق الوحدة الواحدة).
- **0.5.2:** حفظ/تحميل تلقائي — فروق الخلايا المتأثرة + موضع اللاعب عبر `saveSystem.ts`
  (تحميل عند الإقلاع، حفظ عند `pagehide`).
- **0.6+:** تحميل/تفريغ الوحدات حول اللاعب (عتبة مسافة)؛ ثم الكائنات الحتمية داخل الوحدات؛
  المخزون والأدوات عبر التماسّين في `blockInteraction`.

## اتصال تحميل الوحدات (Chunk Loading) بالمعمارية

1. `chunkGenerator` نقي وحتمي من (بذرة، chunkIndex، chunkY) → أي وحدة تُبنى/تُعاد في أي وقت،
   على أي ارتفاع.
2. `world.getChunksInRange(bx0, bx1)` — الاستعلام الأفقي، و`getChunksInRangeY` عمودياً،
   و`getChunksInRect` للمنطقة الكاملة ثنائية الأبعاد التي يقرر بها المحمّل التحميل/التفريغ.
3. علم `Chunk.modified` يفصل الوحدات القابلة للتفريغ مجاناً (سليمة، تُعاد توليدها)
   عن التي يجب حفظها أولاً (متأثرة) — شرط مسبق للتفريغ الآمن.
4. `blockRenderer` يكرر الوحدات صراحةً → إضافة نظام تحميل لا يمس أي نظام آخر.
