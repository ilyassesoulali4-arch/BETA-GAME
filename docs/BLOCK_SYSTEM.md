# نظام الكتل (Block System)

## النموذج

العالم **شبكة كتل** (block grid): كل كتلة خلية مربعة بمقاس `CONFIG.block.size` (24px).
إحداثيات الكتلة: `blockX = floor(worldX / size)`، `blockY = floor(worldY / size)` — `Math.floor`
يعالج القيم السالبة بشكل صحيح.

## الفصل بين الطبقات

| الطبقة | الملف | ماذا تحتوي |
|---|---|---|
| التعريفات | `blockTypes.ts` | سجل ثابت: id, name, color, solid (Air/Grass/Dirt/Stone) |
| البيانات | `chunk.ts` (`Chunk`) | `Uint8Array(size*depth)` — أرقام ids فقط، بلا معنى |
| التوليد | `chunkGenerator.ts` | يملأ بيانات الوحدة حتماً من البذرة |
| التخزين | `world.ts` (`World`) | `Map<"chunkIndex,chunkY", Chunk>` + استعلامات + تتبع تعديلات |
| العرض | `blockRenderer.ts` | يرسم المرئي فقط من قراءة المخزن |

**قاعدة:** التعريفات لا تخزن حالة، والبيانات لا تعرف معناها، والتخزين لا يرسم، والعرض لا يغيّر.

## تخزين الوحدات

وحدة = منطقة مستطيلة `512` عمود × `256` صف:
`data[row * 512 + col]`. تُعرَّف الوحدة بمؤشرين: `chunkIndex` (أفقي، فوق الأعمدة)
و`chunkY` (رأسي، فوق الصفوف) — مفتاحها في `world` هو `"chunkIndex,chunkY"`.
تُولَّد كسولاً عند أول وصول (`world.getChunk(chunkIndex, chunkY)`) وتُعاد توليدها
حتماً في أي وقت — بلا تخزين دائم حتى الآن.

**لماذا `chunkY`؟** كل صف ينتمي لوحدة ما، فالعالم لا نهائي عمودياً:
الصفوف فوق السطح تقع في وحدات علوية (كلها Air)، والصفوف العميقة في وحدات سفلية
(كلها Stone)، والسطح في الوحدات الوسطى (الطبقات المعتادة). البناء يرتفع بلا سقف.

## التوليد

لكل عمود في الوحدة: `surfaceRow = floor(terrain.getHeightAt(centerX) / size)`
(صف مطلق) ثم لكل صف محلي `row` يقابله الصف المطلق `row + chunkY*256`:
- `row === surfaceRow` → **Grass**
- `surfaceRow < row <= surfaceRow + dirtDepth(3..5 حتمي)` → **Dirt**
- أعمق → **Stone**
- أعلى من السطح → **Air** (بلا تغيير عن سابقاً — التوليد نقي ودالة في
  `(بذرة, chunkIndex, chunkY)`).

## البناء والهدم (مستقبلاً)

نقطة الدخول الوحيدة: `world.setBlockAt(bx, by, id)`. الهدم = كتابة `BlockId.Air`.
العرض يقرأ المخزن كل إطار → أي تغيير يظهر فوراً. عند النضج يُضاف `dirty` flag
لإعادة رسم الوحدة المتأثرة فقط.

## الحفظ والتحميل

التوليد حتمي من البذرة، لذا نحفظ:
1. البذرة (هوية العالم).
2. **التعديلات فقط** (differences) لكل وحدة متأثرة: قائمة `(localX, localY, id)`.

**التدفق:** `World.setBlockAt` يعلّم الوحدة `modified`. عند الحفظ، `world.getSaveData()`
يُعيد توليد التضاريس في الذاكرة ويقارن خليةً خلية — فقط الخلايا المختلفة تُسجَّل.
الوحدة المعلمة `modified` التي عادت لمطابقة الأصل (تراجع اللاعب عن تعديل) تُستبعد تلقائياً.

**الطبقات:**
- `World.getSaveData() / applySaveData()` — حساب الفروق وتطبيقها (بلا أي I/O).
- `saveSystem.ts` (`SaveSystem`) — التنسيق (seed + موضع اللاعب + الفروق) والتسلسل
  JSON والتحقق من الإصدار عبر localStorage.
- `main.ts` — تحميل عند الإقلاع، حفظ تلقائي عند `pagehide`.

**أمان الإصدار:** `FORMAT_VERSION` في `saveSystem.ts`؛ النسخ الأحدث تُرفض على التحميل
بدل تفسير خاطئ، والهجرة لاحقاً تُضاف كفرع.

**الحجم:** الحفظ يحوي الخلايا المتأثرة فقط → ضئيل مهما كبر العالم المكتشف.

## ملاحظة أداء: hot-cache

قراءات/كتابات الكتل محلية مكانياً (العرض يمشي الخلايا، التصادم خلايا اللاعب القليلة)،
فمعظم الاستدعاءات تصيب الوحدة نفسها. `world` يخزّن آخر وحدة محلولة
ويعيد استخدامها بدل تكرار تخصيص مفتاح نصي + بحث `Map` في المسار الساخن —
تحسين أداء خالص بلا أي تغيير سلوكي.
